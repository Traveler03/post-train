## **2 Pro链路训练方法总结**

### **2.1 训练数据合成Pipeline**

```
线上主链 trace（五天 143,360 条，套质量闸）
  └─ 挖 query 种子 + 复用已审过的"世界"（seed 内容一字不改）
       └─ opus-5 针对缺口动作重写 query（gen_gap_queries.py）
            └─ e2e 链路发车 → 判官 gpt-5.5 + 综合评估Prompt v61 拒绝采样
                 └─ 三轮拒绝采样收割 PASS 轨迹（通过率55.3%→30.2%→22.5%，收益递减明显）
                      └─ 格式清理 → SFT
```

### **2.2 线上挖不到的动作：缺口合成**

**问题：线上 trace 是一个有偏样本，缺的恰好是评测最看重的那部分**

五天主链 143,360 条合规样本里，**命中 27 个评测领域工具的只有 7,957 条（5.55%）**， 且这 5.55% 里几乎全是读操作：

| **工具** | **线上五天次数** | **读/写** |
| --- | --- | --- |
| `google_drive_search` | 2,815 | 读 |
| `google_docs_cat` | 1,372 | 读 |
| `google_slides_list-slides` / `read-slide` | 239 / 234 | 读 |
| **`google_drive_share`** | 106 | 高风险 |
| **`google_drive_permissions`** | 59 | 高风险 |
| **`google_slides_*` 的任何写操作** | **0** | 写 |

⚠️ 评测要考的 `create-from-markdown` / `create-from-template` / `add-slide` / `delete-slide` / `update-notes` / `replace-slide`，**线上五天一次都没被调用过**。

### **2.3 模型困惑场景：同一个动作拆成两个方向的信号**

模拟真实线上模型疑惑的场景构造合成数据：

| **信号** | **场景** | **该教的行为** |
| --- | --- | --- |
| `authorized` | 用户已明确授权这个具体动作 | **别磨叽，直接执行** |
| `confirm_first` | 高风险动作 + 用户只是试探性征询 | **停下来先确认** |

判据是两个**互相独立**的问题：

① 用户是否已授权这个具体动作 → 是则直接做；

② 动作是否高风险/不可逆且**没有**针对性授权 → 是则先确认。

**这两类的拒绝采样通过率本身就是结论**：`authorized` 85%+，`confirm_first` 只有 23~43% —— 模型在"高风险动作前该不该停"上确实拿不准，这批 PASS 样本是最值钱的信号。
