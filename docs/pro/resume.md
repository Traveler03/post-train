## 推荐投递版（四条）

### Pro 主链路 Agent 数据合成与 LoRA SFT｜DeepSeek-V4-Flash、Megatron-Bridge

面向邮件、日历及 Drive／Docs／Slides 等个人办公场景，独立负责 Pro 主链路的数据合成与 LoRA SFT，优化多轮工具调用、复杂任务执行及授权判断能力。

- **数据合成与筛选：** 分析线上轨迹的任务分布、工具覆盖和失败模式，完成主 Agent 行为归属与当前请求抽取；针对文档编辑、Slides 操作和权限管理等低覆盖能力，复用可执行环境构造任务，经多轮 Rollout、规则校验与 LLM 判官拒绝采样生成训练轨迹。
- **多轮监督建模：** 设计 `messages / tools / sup` 训练格式，区分 system、用户、历史 assistant、工具返回与当前目标动作，处理工具调用—返回配对、历史轮 loss mask 和结束标记；v7 全量校验 1,102 条训练样本、6,134 个受监督 assistant 段，监督角色与 mask 无错位。
- **长上下文 LoRA SFT：** 基于 Megatron-Bridge 适配 DeepSeek MoE，在 43 层 MLA 注意力的 Q down/up、KV 和输出投影挂载 LoRA，仅训练 38.4M 参数（0.09%）；结合 98,304 token 窗口、CP=4、EP=8、激活重计算和整轨迹编码完成 v7 训练，实际运行 276 步、约 2 个 epoch，并保存最终 checkpoint。
- **训练反馈驱动数据选择：** 以 grad norm spike 为线索构建 v2.1／pc8，删除 92 条（8.01%）而基本保持主要工具分布；前期四档相近 epoch 的同题配对综合通过率平均 +4.34pp，作为单轮观察结果报告。

## 30 秒开场

> 我独立负责 Pro 个人办公助手的数据合成与 LoRA SFT，主要优化多轮工具调用中的复杂操作、授权判断和任务完成能力。我从线上轨迹分析能力缺口，在可执行环境中构造任务并筛选 Rollout 轨迹；训练侧完成多轮监督建模和 98k 长上下文 LoRA SFT，再根据 grad norm spike 反查数据、构建过滤版本并重新评测，形成训练反馈驱动的数据迭代闭环。

## 90 秒展开

> Pro 主要处理邮件、日历、文档和文件管理等办公请求。这些任务通常需要连续调用工具，模型既要找到正确对象，也要理解当前用户是否已经授权具体操作。
>
> 我独立负责数据合成和 LoRA SFT。数据侧先分析线上执行轨迹，区分主 Agent 动作、历史上下文和平台过程，识别目标操作的覆盖缺口。针对复杂编辑、权限等场景，我基于可执行环境构造任务，让 Agent 实际执行，再通过规则和判官筛选形成训练数据。
>
> 训练侧，我重点处理多轮监督边界。历史和工具返回作为上下文，当前任务中选中的模型动作参与监督；同时完成工具调用格式、LoRA 挂点和长上下文打包适配。整轨迹处理可以减少重复编码，但还要检查前缀、监督位置以及每步监督 token 数。
>
> v7 最终使用 1,102 条轨迹完成 276 步、约 2 个 epoch 的训练并保存 checkpoint。训练没有 NaN 或跳步，但 grad norm 出现尖峰；部分尖峰在下一个 epoch 的相近位置复现，因此我将其作为数据排查信号，构建去 spike 数据的 v2.1／pc8。
>
> 与原版训练 pc7 按相近 epoch、同题对比，pc8 在前期四档的综合通过率提升 2.44～5.93 个百分点，四档平均 4.34 个百分点。Drive 四档都提高，Docs 和 Slides 有升有降。这是单轮、前期观察，不能当作稳定或最终增益；历史原始选择脚本仍未恢复，新增指纹清单是事后差分结果。

## 如何选面试展开点

准备三个本人最熟悉的案例：

1. **数据案例：** 为什么某类任务需要合成，环境和标准怎样定义。
2. **训练案例：** 一次 mask、格式、LoRA 挂点或长上下文问题的定位。
3. **实验案例：** 一组有效对照，包含改善、退化及仍不能下结论的部分。

每个案例都按“问题、依据、修改、验证”展开。详细追问见[面试准备](interview.md)，效果来源见[评测与结果](evaluation.md)。
