# Pro 面试准备

## 1. 你具体做了什么？

本人独立负责数据合成与 LoRA SFT 全流程。回答时先讲一个具体模块，再说明输入、输出、设计决策和验证。

可以分成：线上分析与清洗、缺口任务合成、轨迹筛选与转换、LoRA SFT、结合评测的迭代。不要把所有外部平台与产品服务都归为自己独立建设。

## 2. 为什么需要合成数据？

真实轨迹用于保留线上任务分布；合成用于补充经过筛选后仍缺失的目标动作，并控制授权、对象、环境等条件。

区分原始流量和训练候选。五天 5.55% 的统计属于特定候选与工具范围，不能推成全线上都缺写操作。样本多不代表目标能力覆盖充分。

追问：怎么配比？回答应结合线上占比、业务重要性、验证表现和退化；当前材料没有统一的配比消融，不能编造最优比例。

## 3. 任务环境怎样保证能执行？

环境中要有被操作的对象，身份、权限、时间和工具 schema 要一致。例如分享对象需要被环境接受；不存在的文件或不可用的收件人会让任务在环境层面失败。

先检查可执行性，再评价模型是否完成任务。参数格式合法不代表对象正确，也不代表行为符合用户意图。

## 4. 如何教模型授权判断？

用同一类动作下的不同决策条件解释：

| 情境 | 正确行为 |
|---|---|
| 已明确授权分享指定文件给明确收件人，权限也已确定 | 核验对象后执行 |
| 只讨论是否对外公开，没有授权 | 先确认 |
| 文件或对象有歧义 | 先澄清 |
| 请求合理但工具失败 | 基于实际结果处理和说明 |

这类示例用于阐释数据设计，不能声称所有样本都是严格配对实验。不要把“谨慎”简化成所有操作都先问。

## 5. 判官可靠吗？

把质量分成环境正确、执行完整和语义交付。前两类尽量做确定性检查，语义部分结合判官，保留标准与结果来源。

判官存在误判、共同偏差和波动。最终成功也可能包含冗余操作或错误恢复。可以提出分层人工抽审、困难负例和争议样本复核；没有做过的验证应表述为后续改进。

多次判定不等于多个独立判官，多次出现 PASS 不自动证明每个中间动作都正确。

## 6. SFT 的 loss 算在哪里？

当前任务中被选中的 assistant 输出参与监督，包括配方选定的思考、工具调用和答复。System、工具定义、用户输入、历史和工具返回提供上下文。

工具结果不计直接监督，不等于从输入删除。当前动作不能看到未来工具结果。需要解释 labels 与 mask 的 next-token 移位，以及结束符为什么也可能是目标的一部分。

准备一条脱敏的示意轨迹，在消息层标清历史、当前请求、调用、返回和最终答复。不要直接展示含用户隐私的原始日志。

## 7. 整轨迹与逐轮训练有什么关系？

逐轮训练反复编码前缀；整轨迹编码一次，对多个输出段监督。

要核验三个条件：对应 token 前缀相同、监督 token 相同、目标权重对应。因果注意力保证当前预测不读取后续 token。

即便数据表示对应，训练 batch、更新频率和随机性仍会变化。整轨迹后每步监督 token 密度提高，需要重新核算训练设置。不能宣称完整训练过程必然逐步相同。

## 8. Packing 怎么避免样本互相看见？

通过分段信息控制注意力，分段重置 position_ids，并排除跨样本预测目标。仅重置位置不足以隔离样本。

常见错误：上一条样本的末尾预测下一条开头；mask 与 label 移位不一致；padding 参与监督。这些问题可能不会表现为明显的 loss 异常。

## 9. LoRA 挂在哪里？MoE 的专家和 router 训了吗？

当前默认挂 MLA 注意力投影：linear_q_down_proj、linear_q_up_proj、linear_kv_proj、linear_proj。

MLP 有额外开关；router 不在这份 target 列表里。实际运行应核对 adapter 列表与可训练参数，不能仅凭启动参数推定全部挂载成功。

解释为什么不能直接套普通模型的 linear_qkv 模块名，是一个具体适配经验。

## 10. 为什么要长上下文？怎样处理显存？

工具定义、历史和工具结果会占据大量上下文，截掉它们可能改变动作所依赖的信息。

LoRA 减少可训练参数相关开销，但激活仍然昂贵。CP、Packing、整轨迹处理、激活重计算分别解决序列分布、padding、重复前缀和激活存储问题。

参数卡见[LoRA SFT](lora-sft.md)。解释采用某个配置的依据时区分启动配方和已完成消融，不把默认值称为最优。

## 11. 如何证明评测提升来自训练？

核对实际模型与 adapter、思考档位、工具环境和判官版本，使用同时段的底座对照，并保留多轮和逐题结果。

分别统计模型答错、执行故障和判官未完成。不能只在成功完成的题上算分，也不能对正常错题无限补跑。

Pro 总体提升下仍有子类退化，应准备一个反例解释。详见[评测文档](evaluation.md)。

## 12. 数据泄漏如何防？

区分题目、来源和环境三个层次。来自同一规则、用户或会话的数据存在相关性；随机按行切分不够。

代码按选定 group 切分，但 OpenAI 路径优先 question／iid，并不自动等于 session 或 source_rule_key。应检查实际 group 含义和来源交集，不能仅依据元信息中的“按组切分”字样下结论。

## 13. 为什么先做拒绝采样＋SFT，而不是直接 RL？

这一阶段需要覆盖业务动作、稳定工具协议，并获得可复用轨迹。拒绝采样把任务级验证结果变成可监督样本，SFT 便于控制数据和格式变量。

局限是失败信息利用不足、通过轨迹中间动作未必最优、难题可能始终采不到通过样本。后续偏好学习或强化学习还需要处理判官噪声、环境成本和多轮信用分配。

现有代码中存在偏好对导出或相关方案，不等于已完成 DPO／KTO／在线 RL 并取得效果。

## 三个必须准备好的材料

- 一条完整示意轨迹：能现场标出每段的角色、可见信息和监督边界。
- 一张真实实验配置卡：数据版本、LoRA 挂点、上下文、batch、学习率和 checkpoint。
- 一个失败复盘：现象、判断依据、具体修改、验证结果与局限。
