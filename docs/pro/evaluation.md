## 3. 子类改善与退化

Pro 报告显示总体改善并不均匀：

- Drive 的部分增益来自读取与取数、负向与歧义、评论等子类。
- Docs 的精确编辑和评论有所提高，但新建与写入出现退化。
- Slides 的改页与备注、高风险情境等有所提高，但创建类存在退化。

子类样本量可能很小。报告中有个别四舍五入差异；讨论细分数字时应直接核对对应表格和原始结果，不凭总体提升推定所有能力都提高。

## 4. 比较条件

一次可解释的比较至少应记录：

| 维度 | 需要保留的内容 |
|---|---|
| 数据 | 版本、筛选配方、来源、样本量与监督 token |
| 训练 | 代码版本、超参、随机种子、checkpoint |
| 执行 | 实际模型、adapter、思考档位、输出预算 |
| 环境 | 工具 schema、账号／环境版本和运行时段 |
| 评分 | 判官模型、评分规则版本、分母与缺失情况 |
| 结果 | 每轮分数、逐题记录、子类与失败类型 |

同名模型可能因为平台构建、工具形态或推理设置不同而产生明显差异。仅比较历史最好分数不足以说明训练收益。

## 5. 故障与任务失败

- 缺 trace、空执行结果、明确推理异常属于执行完整性问题。
- 有正常回答但未完成任务，属于模型表现。
- 有答案、判官尚未落库，需要等待评分完成。

不能只对留下来的成功执行计算分数而忽略缺失题目。也不能把正常答错的题一直重跑到正确。

仓库有评测恢复与执行失败补测实现，本次此前运行相关 4 项离线测试通过；这不代表已重跑线上评测。

## 6. 波动与选择偏差

关键结论应复测，保留每轮结果。需要估计不确定性时，应考虑同一任务的配对关系，而非把重复 run 当作完全独立样本。

多次评测并挑最高 checkpoint 会引入选择偏差。最终结论最好使用独立验证／测试安排，并同时报告退化案例。若没有训练多种子对照，不要声称已经排除训练随机性。

## 8. 成果表述

> 在已记录的同 Low Thinking 档位评测中，后训练模型在 Drive／Docs／Slides 的通过率分别提升 4.93／5.03／3.22 个百分点。

若追问具体训练版本，可补充：

> v7 使用 1,134 条 v2 数据训练，历史 run 在多个 checkpoint 上评测，`s162` 首次结果为 Drive 87.4%、Docs 83.3%、Slides 83.0%；复测显示波动较大。后来继续做了去尖峰数据、多轮数据和环境对齐迭代，最终项目统一口径的提升是 4.93／5.03／3.22pp。

若加入数据规模或效率收益，应确认与这组结果属于同一版本或明确区分批次。AutoTask 的效果和槽位优化数字见[补充资料](../reference/autotask.md)，不混入本表。
