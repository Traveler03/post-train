# Pro LoRA SFT

## 1. 本人负责范围

独立搭建从执行轨迹到 LoRA SFT 的数据与训练流程，包括消息转换、监督掩码、序列处理、LoRA 适配、训练配置与 checkpoint 产出。

当前材料中可核验的训练入口基于 Megatron-Bridge，模型目录标签为 DeepSeek-V4-Flash-0731。具体参数按启动脚本和实际运行日志区分。

## 2. 多轮监督目标

| 内容 | 输入用途 | 直接监督 |
|---|---|---|
| System、工具 schema | 角色约束与动作空间 | 否 |
| 当前用户请求 | 任务条件 | 否 |
| 历史召回、近期历史 | 上下文 | 按来源排除 |
| 平台初始化应答 | 协议上下文 | 否 |
| 当前任务中选中的 assistant 思考、工具调用和答复 | 模型行为 | 是，依实验配方 |
| 工具返回 | 后续动作的环境证据 | 否 |
| Padding、跨样本预测 | 填充或段间边界 | 否 |

目标可概括为：

```text
L = - sum_t(mask_t * log p_theta(x_t | x_<t)) / sum_t(mask_t)
```

工具返回不计算直接监督 loss，但仍参与上下文表示计算。不能提前把某次工具调用之后的结果放入该动作的输入。

### 当前请求边界

Pro 的输入可能包含早期召回、最近对话和当前请求。同一条轨迹中出现 assistant 角色，不代表该消息应参与当前目标。

代码支持保留 `loss: false` 的历史 assistant 消息；同时存在依赖特定消息结构的边界检查。复用这些规则时需要确认数据单元，不能对任意多用户轮会话机械套用相同边界假设。

## 3. 消息和结束标记

工具调用参数也属于模型输出。消息转换需要保证文本、工具调用和工具结果的对应关系，避免：

- 把一次输出中的文本和调用拆开后插入不该有的结束符。
- 工具调用与返回断链。
- 历史、用户或工具文本误进入监督。
- 最终答复标记与实际任务结束方式不匹配。

Loss 下降不能证明这些转换正确；需要直接检查渲染结果和监督位置。

## 4. LoRA 挂载

当前 `train_dsv4.py` 默认目标为 MLA 注意力投影：

| 模块 | 作用 |
|---|---|
| `linear_q_down_proj` | Q 投影的低秩部分 |
| `linear_q_up_proj` | Q 投影的上投影部分 |
| `linear_kv_proj` | KV 投影 |
| `linear_proj` | 输出投影 |

设置 `LORA_TARGET_MLP=1` 才额外加入 `linear_fc1` 和 `linear_fc2`。Router 未出现在此目标列表中。

不能从“使用 MoE＋LoRA”推定所有专家或 router 都被训练。最终还需核对环境变量、实际 adapter 列表及可训练参数。

一个实际适配点是：普通模型常见的 `linear_qkv` 名称不适用于该 MLA 结构。启动成功不代表所有预期层都挂载了 adapter。

## 5. 整轨迹渲染与 Packing

逐轮样本会为每个目标动作重新编码此前所有上下文。整轨迹渲染将轨迹编码一次，在多个 assistant 段上设置监督。

### 需要满足的检查

1. 逐轮样本等于整轨迹的对应 token 前缀。
2. 对应的监督 token 与位置一致。
3. 当前动作无法看到未来工具结果。
4. 不同样本之间的注意力和预测边界隔离。
5. 有效监督 token 采用对应的权重归一方式。

Packed 数据提供器使用 `cu_seqlens` 表达分段，分段重置位置，并将跨样本预测的 loss mask 置零。只重置 position_ids 不足以保证注意力隔离。

超窗样本可以在可容纳的完整 assistant 消息处截断，但这意味着部分样本没有最终交付轮，需要记录和分析。

### 效率数字的使用边界

仓库里的 3,749→896 窗口、约 76% 槽位减少，来自 AutoTask 的已记录批次，不能作为 Pro 的实测效率成果。Pro 简历可以描述整轨迹处理与打包实现；量化收益应补 Pro 自己的数据统计或耗时对照。

Token 前缀与监督位置对应，不等于完整训练动态必然相同。Batch、每步监督 token、梯度累积、更新次数及随机性都会影响结果。

## 6. Pro v7 配置卡

依据 `launch_prochain_v7_milly_0827.sh`：

| 参数 | 配置 |
|---|---|
| 模型目录标签 | DeepSeek-V4-Flash-0731 |
| 框架 | Megatron-Bridge |
| GPU 进程数 | 8 |
| 并行 | TP=1，PP=1，EP=8，CP=4 |
| 序列长度 | 98,304 |
| Packed | 开启 |
| 激活重计算 | full |
| LoRA rank／alpha／dropout | 16／32／0.05 |
| 学习率／最小学习率 | 1e-4／1e-5 |
| Global／micro batch | 8／1 |
| 步数 | 276，脚本标注约 2 epoch |
| 存档间隔 | 27 steps |
| MTP | 关闭 |

这是一个具体启动配方，不能代表所有 Pro 实验。通用入口里有旧默认值和旧注释，应以本次启动参数及实际运行日志为准。

并行维度存在重叠关系，不应直接将 TP、PP、EP、CP 全部相乘推算 GPU 数。LoRA 减少可训练参数和相应优化器状态，但长序列激活仍然昂贵；CP、Packing 与重计算分别解决不同部分的问题。

## 7. 数据切分的实际边界

代码按选定 group 切 train／val。OpenAI 路径优先采用 question／iid，再回退 meta.rule_head；另一条路径优先采用 meta.rule_head／trace_id。

这不自动构成规则、用户或会话级隔离。特别是不同 question 对应同一来源规则时，仍需额外核验来源交集。数据转换产物中的“按组切分”标签不能替代检查 group 的实际含义。
