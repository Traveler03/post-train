### 1281 → 6257:逐监督轮"爆破"

一道题模型要来回好几轮,**每次开口都是要教的东西**。一个真任务(爆破成 5 条):

```
sup_turn= 4   前缀=前 4 条消息   ← 教「看到这些,该调 memory_search」
sup_turn= 6   前缀=前 6 条消息   ← 教「拿到结果,该接着查」
sup_turn= 8 / 11 / 13            ← … 直到「最后写这个答案」
```

每条样本的前缀是"到这轮为止的对话",**loss 只盖最后一段**。
中位 5 条/任务、最多 18;1281 × 4.9 ≈ 6257。

## 三、哪些 token 算 loss:只有被监督那一轮的「思考 + 输出 + 结束符」

```
token 总数        332,138,424
进 loss 的          8,928,285 = 2.69%
每样本进 loss 的    中位 934 个,最多 13,311 个
样本长度            p50 50,327 · p90 78,877 · max 98,121
```

解一条样本的掩码(样本#10,53,133 token):

```
掩码位置 51450 ~ 53132,连续一整段
⇒ 前 51,450 个 token 只当上下文;最后 1,683 个算 loss
```

那 1683 个 token 解出来是:

```
<think>Now I have the full picture from memory. Let me assemble the context: …
                                          ← 这一轮的思考
{"content": "...", "pass": true, ...}      ← 面向用户的输出(信封)
<｜end▁of▁sentence｜>                       ← 结束符也进 loss(学会收尾)
```

**平均 5 万 token 的上下文,只教 934 个 token** —— 这就是 2.69% 的来处。

## 四、「vLLM 服务丢历史轮思考」是错的(0819 实测三层)

`prepare_dsv4_data.py` 原注释:*"服务渲染上下文时丢历史轮思考,所以整条渲染会与服务
相悖,逐轮爆破是唯一自洽解"*。三层都不成立:

| 层 | 注释说的 | 实测 |
|---|---|---|
| 编码器 | `drop_thinking=True` 会丢历史思考 | **只在没有 tools 时才丢**。`encoding_dsv4.py:564-567` 里 `if any(m.get("tools")...): effective_drop_thinking = False`;我们永远带 27 个工具 schema ⇒ **开关空转**。四种组合实测:带 tools 时 True/False 都保留 2/2 |
| 线上服务 | 丢历史轮思考 | 1600 份 worker 落盘(ADK 原件)零例外:最后一条 user **之后** 304/304 = 100% 带思考;**之前** 0/155 |
| 我们的数据 | 因此必须逐轮爆破 | 见第二节,99.8% 都在 ⇒ **训推没有不一致** |

线上真实结构是**四段消息**:

```
[0] system
[1] user            ← 任务
[2] assistant       ← 短应答,无思考
[3] user            ← tick(最后一条 user)
[4..] assistant/tool 交替 —— 循环内每轮思考全保留
```

**最后一条 user 就是那个 tick**,所以 agent 循环内每一轮的思考线上全都保留;
丢的只有 tick 之前那个短应答轮 —— 而它本来就没有思考。

### 那道自证闸为什么没拦下来

`_thinking_explode_proof` 调编码器时**不传 tools**,而真实渲染路径注入了。
⇒ 闸走「无 tools → 真会丢思考」那一支,数据走「带 tools → 不丢」那一支。
**闸验证的是一条我们不走的路径,从来没在真数据上响过**;而且它的断言本身也是反的。

已重写(commit `a7b04b2`):走真路径,断言改成真正会出事的那条 ——
**不许有「排在最后一条 user 之前、却带思考」的 assistant 轮**。

### 代价:4.3 倍算力

```
现在(逐轮爆破)  332,138,424 token
整条渲一次        76,608,004 token
⇒ 4.3× ,重复的部分 255,530,420 token,而 loss token 一个不少(8,928,285)
```

一个任务的 5 条样本长度是 32k / 49k / 49k / 49k / 53k —— 后四条几乎一样,
因为**每条都把整道题的上下文(含 105KB 工具返回 + 23k token 工具 schema)重装一遍**。

## 四点五、【0819 下午已改】新实验一律整条渲染,`--render whole`

上面那句「不为省算力改正本」当天下午就落地了 —— 等价性验完了,而且**梯度逐 token 相同**。

### 三层证据

| 层 | 怎么验的 | 结果 |
|---|---|---|
| 前缀 | 6 个任务 24 个轮次,`render(前缀 k)` 和 `render(整条)[:len]` 逐字符 + 逐 token 比 | **24/24 一致,0 处分歧** |
| 掩码位置 | 20 个任务,监督区的**绝对下标** | **20/20 完全重合** |
| 归一化 | `train_dsv4.py:181 calculate_per_token_loss = True` | 按全局监督 token 归一 |

机制:编码器里唯一会让「中间轮」和「末轮」渲得不一样的是 `drop_thinking` 那条分支,
而我们的样本永远带工具清单,`encode_messages` 看到 `tools` 就把这个开关强制关掉
(`encoding_dsv4.py:564-567`)⇒ 渲染是**流式**的,加消息只往后接、不回头改前面。
因果注意力下第 k 轮只依赖它前面的 token,三条合起来 ⇒ 两种渲染的梯度是同一个东西。

打包也不拦路:`pack_dsv4_windows.py` 只管把整条样本首尾相接,一条样本内部掩码断成
几段它根本不看;`cu_seqlens` 保证窗口内不同样本互不可见、`position_ids` 每段重置、
跨段边界的预测不进 loss。

### 省多少(打包模拟能复现线上产物的 3749 窗口 / 90.1% 装填)

| | 样本 | token | 窗口 | 装填率 | 总槽位 |
|---|--:|--:|--:|--:|--:|
| 逐轮爆破 | 6257 | 3.32 亿 | 3749 | 90.1% | **369M** |
| 整条渲染 | 1281 | 0.77 亿 | 896 | 87.0% | **88M** |

**4.19 倍。** 保住的 assistant 轮两边都是 **7538** 个(一条不多一条不少);
40 题实跑对拍,两边 loss token 都是 **148,846** 个。

### 一条样本的 token 花在哪(30 个任务的中位数)

| 成分 | token | 占比 | 算 loss |
|---|--:|--:|---|
| 工具 schema | 19,703 | **37%** | 否 |
| 工具返回原文 | 19,919 | **37%** | 否 |
| 题面 + tick | 9,120 | 17% | 否 |
| 系统提示词 | 2,624 | 5% | 否 |
| 模型的思考 | 2,357 | 4.4% | **是** |
| 模型的正文 / 工具调用 | 941 | 1.7% | **是** |

要教的只占 6%(其中 71% 是思考)⇒「前缀被重复编码几次」是唯一值钱的杠杆。
loss 密度:爆破 2.69% → 整条 11.8%。

⚠️ **工具 schema 占 37%,而它随平台换工具就过期** —— 教材的保质期不按天算,
按「平台换没换工具」算。当前 v3.1.7 教材:1075 个任务(83.9%)是灰度形态
(15 工具、挂 `tool_search`),**206 个任务(16.1%)是已下架的对照形态**
(27 工具直挂 Google),其中 **444 个轮(41%)在直调今天发不出去的工具**。

### 换过去必须一起补的四件事(都已落地)

1. ⛔ **tick 前那句罐头应答不能进 loss。** 它是 ADK 塞进输入的上下文,不是我们的输出
   (实测 1281/1281 个任务恰好 1 条,无思考无工具调用)。爆破路径是**碰巧**排掉它的
   —— 靠严格版形状闸;而 `build_sample` 里那道同名的闸写坏了:
   `if not (is_env or is_call or len(seg.strip()) > 0)`,只要段非空就放行,
   **从来没响过**。实测整条渲染会因此每 20 个任务多 560 个 loss token。
   现在显式排除,判据是**结构**(排在最后一条 user 之前)不是字符串 ——
   平台改措辞 / 改语言 / 不发 / 发两条都自适应。
2. **`build_sample` 透传 `reasoning_effort`。** 老代码不传,编码器按默认 low 渲;
   这份语料全是 low 所以当时没错,但做严格 high 对照臂会**静默**渲成 low。
3. **超窗任务「渲到最后一个装得下的轮为止」。** 整条长度 p99 = 142,470、最长 368,848,
   窗口 98,304 ⇒ **51 个任务(4.0%)超窗**,整条丢掉会连带损失 382 个轮。
   截断之后丢 **0** 个任务,丢掉的轮恰好是爆破本来也丢的那 110 个。
4. **超参要重调。** 每窗口的 loss token 从 2,381 涨到约 9,960 —— 同样的 global batch
   会让每步梯度样本量涨 4.2 倍、一个 epoch 的步数少 4.2 倍。学习率和梯度累积必须一起重算,
   否则等于偷偷把 batch 放大了 4 倍。二阶效应:在「每步 loss token 对齐」的前提下,
   一步覆盖到的**不同任务数变少**(一步看几个任务而不是几个轮),多样性略降。

### 两道闸(重点不是"闸存在",是"闸会响")

| 闸 | 在哪 | 拦什么 |
|---|---|---|
| A | `structure_issues()` | 平台改了那四段消息的结构 → 当场停机。逃生口 `--allow-structure-outliers`,默认 0 |
| B | `_render_equivalence_proof()` | 每次跑数据复查一遍「整条 == 爆破」(逐 token + 掩码位置) |

⭐ `_thinking_explode_proof` 那道老闸写了但**走的是我们不走的路径**(不传 tools),
所以从来没响过。所以这两道闸都做了注入验证 —— 三种注入实测都停机:
罐头应答漏进 loss / 掩码错位 / 渲染不再是流式的。19 个测试焊在
`training/scripts/dsv4/tests/test_render_modes.py`(用假编码器,不加载真模型,0.13 秒跑完)。

### 怎么用

```bash
# 新实验:必须显式给 --render,没有默认值
python3 training/scripts/dsv4/prepare_dsv4_data.py \
  --src <sft_samples.jsonl> --src-format openai \
  --thinking-mode thinking --render whole --reasoning-effort source \
  --out-dir <数据目录>
```

⛔ **`--render` 故意不给默认值**:默认 `whole` 会让人复现旧实验时静默拿到新渲染,
默认 `explode` 会让新实验白烧 4 倍算力。**会骗人的默认值比没有默认值更糟**
(`harvest_select` 那个 `hy3-low` 兜底值的教训)。`meta.json` 记 `render`,
同一个目录里混两种渲染直接拒绝。

## 五、`low_confidence` 是我们自己给的,而且 v3.1.7 那 97 条冤枉了

`harvest_select.py`:`low_confidence = (n_verdicts < 2)`,
`n_verdicts` = 这道题**真的拿到过几个判定**(PASS/FAIL 都算)。渲染默认剔掉。

判据本身没错(两轮翻转 26.8%,单判定的 PASS 有相当概率是判官抖动),
错在**它是收割那一刻的瞬时值**,写进 `sft_pass.jsonl` 就成了永久属性,没人回头重算。

```
v3.1.7 的 sft_pass 收在 0816 05:19,那时 r2p2 三块还没跑完
  → 97 个任务当时只有 1 个判定 → 全被标 low_confidence → 渲染剔掉

等 r2p2 跑完后回查 rows.jsonl:
  73/97 = 75% 已经有 ≥2 个判定
  组合:PASS+PASS 34 · FAIL+PASS 28 · 更多轮 11
```

⚠️ **不是「过了就不重跑」** —— 实测第二轮基本是全量重跑(PASS 的 1145 个也跑了 r2,
只有 11 个没 r2)。纯粹是收割拉早了。

已加闸(commit `20c207c`):`partial_verdict_gate()` 和**同批中位数**比,
少于中位数的题占比 >2%(且 n≥100)就 fail-closed,名单写进
`<out>/below_median_verdicts.txt`,逃生口 `--allow-partial-verdicts`。

⭐ 判据故意和中位数比、不套绝对阈值:轮次策略变过(固定 5 轮 → 自适应 2 轮),
`all_pass` 那个写死 `len(rs) >= 3` 的判据当场失效、**一次都没触发过**。
