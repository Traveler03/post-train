## 0. 被测 agent 的边界

- 被测/被优化的是 **`assistant_professional`(聊天主链专业版)**:e2e 从 `assistant_router`
  进、判"重"后落到它。
- **AutoTask 提醒链(`remind_agent_professional`)是另一个 agent,不在范围内**;
  实测三天原始 trace 里它零出现,本文统计天然不含它。
- `auto_task_*` 工具是聊天主链里的提醒管理动作(约 1% 请求),属 assistant_professional
  行为但不在优化范围,表格保留仅为完整。
- call_llm 与工具 span 都沿 parent 链归属到发起 agent(§1),router / lite /
  video 内部 / 沙箱的动作不会记在专业版头上。

## 1. 统计口径

- **请求级** = 一个 trace = 用户的一次消息;**会话级** = 按 session_id 聚合该会话
  所有请求的当前轮信息。⛔ 会话统计不能只解析"最长那条"的肚子:平台只留近 5 个
  请求轮、QRC 是压缩改写、工具返回超 2000 字符从中间硬切——最长那条看不见早期轮
  的真实动作,它只用来量"上下文最深多深"。
- ⛔ **工具 span 必须先归属到发起它的 agent** 再统计:router 移交 pro 的
  `transfer_to_agent` 出现在 99.95% 的请求里,不归属会把"零工具"从 31% 压成 0.02%、
  沙箱转交虚高近一倍。归属后断链率仅 1.1%。
- 三天全量工具 span 分桶:沙箱内部 32.5 万 > **模型真实调用 22.8 万** > 路由管道
  19.2 万 > 平台机件 7.9 万 —— raw 的 TOOL span 总数里模型行为只占约 27%。
  下文"调用量"一律指模型真实调用(拆 proxy 壳、剔机件),分母 228,079。

## 2. pro 在被用来做什么

**一句话总览:pro 是"生成内容 + 打理 Google 工作台"的助手**——37% 请求在生成
(视频/图片为主),31% 纯文字对话(大半是追问和闲聊),25% 在操作工具;而且工具活里
**写操作占比高:用户不是在"查",是在让它替自己干活**。

**读法(三条要紧的)**:
- **上下文 token 各族都挤在 6~9 万一档**——被 system+工具定义的恒定约 19 万字符压平,
  任务差异体现在**调用次数和步数**(办公族每请求调用 p50 3~5 次、slides p90 到 16 次),
  不在上下文量;重尾在 sheets(p90 148k)和 people(180k);
- **办公四件套是"多调用、多步 + 写操作重"型**(写占 22~36%)——写=不可逆动作,
  是判官 hard 红线(错发/错删/错改)高发区,也是 drive 靶点"过度确认 vs 该动手就动手"
  的主战场;配方里写场景权重应对齐本表;
- 零工具请求输出极短(p50 233 token、一步收尾);视频类输出最长(方案文案)。

### 2.3 零工具的 31% 在干什么

⚠️ 口径:意图标签打在 **merged_clean(训练语料)的零工具样本**上(gpt-5.4-mini
分类,4,876 条),不是 raw 全量——分布可能受清洗影响,量级判断可用,精确占比慎引。

| 意图 | 占比 | 意图 | 占比 |
|---|--:|---|--:|
| followup(对上文追问/继续/确认) | 26.4% | action_request(要求执行动作) | 4.4% |
| 闲聊寒暄/陪伴 | 24.1% | media_gen 相关对话 | 3.4% |
| 通用知识问答 | 18.2% | personal_data 相关 | 1.1% |
| 写作/改写/翻译/总结 | 9.5% | realtime_info / media_understand | 1.2% |
| (空 query,平台触发) | 7.6% | other | 4.1% |

要点:**零工具 ≠ 闲聊**。followup 是第一大类——多轮任务的中间轮;
"该调没调"(need_tool=yes)只占 6%,不是大盘问题。

### 2.4 query 原文给的三个画像

1. **多语言、口语化、上下文残缺**:泰/印尼/越/日/中/英/葡混杂,大量"就按你说的做"
   "All set! I've finished authorizing."——**OAuth 授权打断后回来接续**是高频模式;
2. **真实工作场景浓度高**:仓库审批邮件、销售 playbook、证券损益整理——错了有真实代价;
3. **生成类是"导演式迭代"**:query 多是对上一版的修改指令("制服别去掉,红队蓝队都要"),
   单发一次成的占少数。

### 5.5.2 覆盖缺口(评测完全测不到的线上大头)

1. **零工具对话 31.1%**:followup 接续、闲聊、知识问答、写作——没有任何一套测;
2. **memory / 长会话**(会话级 14.5%):没有专门集,且所有集都是新账号冷启动;
3. **生成类整体欠权**:线上 37.5% vs 评测权重 11.9%,且没测迭代模式
   (0827 新增的两套 for-work 集补了语种和权重,迭代仍是单轮形式,见 10 号文);
4. **非中文 79% 流量**:除 GAIA(题风不符)外零覆盖;
5. **多轮机制方向相反**:评测的多轮在"模拟用户逼进度",线上的多轮在"接续/改稿/
   授权回来续"——评测催它动手,线上考它接得住。

### 5.5.3 训练数据 vs 评测集:六个 gap

| 维度 | 训练数据(实测) | 评测集(实测) | gap 与后果 |
|---|---|---|---|
| **任务分布** | 大头是生成(video 24.4% + image 12.9%);**办公四件套合计仅 5.5%,drive 只有 1.3%** | 三大目标集 100% 办公 | **倒挂**:7.2 万条语料里 drive 教材只有约 900 条,靶向必须合成;练生成对目标三集零贡献,还要防回归 |
| **语种** | zh 仅 20.9%,latin 系 76% | 几乎 100% 中文 | 评测测不到线上 79% 流量的语种;中文特调可能虚高评测分 |
| **上下文** | 90% 样本带历史(真历史轮 p50 5 / p90 14) | 全新账号冷启动:0 历史、0 QRC | 训练长、评测短:长上下文退化评测发现不了 |
| **多轮机制** | followup 接续 / 授权续 / 迭代改稿 | 脚本式模拟用户逼进度 | 两种能力:前者评测不覆盖,后者是靶点 |
| **世界数据** | 真实账号 + 真噪声(硬切 JSON、空返回) | S3 seed 预置的干净世界 | 合成数据要保留线上式噪声 |
| **监督信号** | 无 gold,只有"模型当时怎么做的" | expected_output + v61 全维 AND 判官 | 直接 SFT 会把线上错误学进来——拒绝采样必须在环 |

一句话:**训练数据和评测集几乎是两个世界**——任务倒挂、语种倒挂、上下文一长一短、
多轮一真一假。配方要显式分两层:靶向合成对齐评测集(拿分),线上分布对齐训练语料
(不伤大盘);验收时办公三集之外带生成/非中文回归探针。

## 6. 对配方的直接推论

1. 样本上下文按 §3 配:**长输入、重工具定义、带 QRC、历史含工具循环**,
   不用评测式冷启动短上下文;
2. 练"接续"能力:followup + 授权回来续 + 生成迭代改稿,是线上第一大交互模式(§2.3/2.4);
3. 写操作按 §2.2 的写占比配权,每个写场景配"该确认 vs 该直接做"的正反例(接靶点聚类);
4. skill / tool_search 装载段是几乎所有工具活的前奏,轨迹里不能洗掉;
5. slides 的"做 PPT"本体在沙箱,主链可训的是读/汇总/转交决策;视频路线决策、
   沙箱转交决策的样本从 raw 侧回填或合成(§5);
6. slides 在线上只有 0.4%,配比别被评测集地位带偏;drive 才是办公头部;
7. 每会话 p50=1 次请求 ⇒ 大部分价值在单请求内闭环;p90=10 的长会话贡献记忆/QRC 场景,
   两头都要覆盖。
