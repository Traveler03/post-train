# docs-replace-or-edit

以最少且可验证的写入完成用户指定的文档编辑，正确处理位置、次数、大小写、字面量和格式约束。

## 工作流

1. **parse_edit_contract**：提取目标文档、原内容或位置锚点、新内容、作用次数、大小写、字面匹配、格式及“其他内容不变”等约束；不得自行扩大范围。（适用条件：所有文档编辑请求）
2. **resolve_target**：在缺少文档标识时定位唯一目标，并核对名称、类型及所属上下文；存在多个合理候选时先消歧。（适用条件：尚未获得可靠的目标文档标识）
3. **ground_scope**：当编辑依赖当前内容、章节边界、相邻段落、文档开头、插入索引或出现次数时，读取内容或结构，确定最小编辑边界。（适用条件：无法仅凭请求安全确定编辑范围）
4. **apply_minimal_mutation**：选择符合语义的最小写入：替换按首处或全部、大小写及字面量执行；空替换表示删除；插入使用已核实位置；结构化内容按请求保留格式。（适用条件：目标和编辑范围均已明确）
5. **check_action_result**：检查写入是否成功、命中数量或插入位置是否符合预期；证据不足、零命中或数量异常时读取当前状态后再决定是否修复，避免重复写入。（适用条件：写入动作已返回结果）
6. **report_outcome**：仅依据动作证据报告实际完成的内容、范围和可证实的次数；失败或部分完成时明确说明，不得宣称全部成功。（适用条件：准备结束任务）

## 决策规则

- 用户已明确要求执行编辑时，该请求即构成对应范围的授权；若系统没有强制确认要求，不应只停留在预览或再次确认阶段。
- 查找文本默认按字面量处理；方括号、尖括号、星号、斜杠等特殊字符不得被误当作正则或参数分隔符。
- “第一处”只允许修改一次，并保留后续匹配；“全部”应修改所有符合大小写和字面规则的匹配。
- 明确区分大小写时，只修改指定大小写形式，其他形式保持不变。
- 章节替换应以目标章节与下一章节边界限定范围；不得连带修改标题或相邻章节，除非用户明确要求。
- 位置插入必须基于已核实的相邻内容或结构索引，并保持前后内容及顺序不变。
- 空的新内容表示删除指定目标，不表示清空文档或删除更大范围。
- 请求包含 Markdown、标题、列表或其他结构要求时，写入内容和格式都必须满足约束。
- 若目标、替换值、章节边界或候选文档存在实质歧义，先澄清，不猜测身份、日期或业务值。

## 停止条件

- 无法唯一确定目标文档，且继续操作可能写错资源。
- 需要依赖当前内容或结构确定范围，但无法取得可靠内容证据。
- 预期应有匹配却返回零命中，或实际命中数量与“首处/全部”等约束冲突。
- 写入动作失败、结果不明或可能已部分生效，且尚未核实当前状态。
- 完成请求需要超出用户授权范围的额外写入。

## 失败恢复

- 搜索结果不唯一时，使用更具体的名称、类型或上下文缩小范围；仍不唯一则请求用户消歧。
- 零命中时重新读取目标片段，检查空白、标点、大小写和边界；不得直接改用宽泛匹配。
- 命中数量异常时停止继续写入，核实当前内容，并以更窄锚点修复剩余授权范围。
- 写入结果不确定时先读取当前状态，再决定是否重试，防止重复插入或二次替换。
- 若仅部分完成，保留已成功部分，明确报告差异，并只对未完成且仍获授权的范围进行修复。
- 无法恢复时如实报告未完成或部分完成，不伪造成功、次数、链接或文档状态。


## 外部变更授权

- 本节是强制策略，覆盖上方任何将初始请求直接视为执行授权的生成规则。
- 用户最初提出变更只表示意图，不视为确认。
- 未确认时，先完成必要的只读定位与检查，展示具体目标及变更预览，并用一个明确问题请求确认；本轮不得写入。
- 只有在后续用户消息明确确认，或上游提供可信的同消息预授权状态时，才执行变更、验证结果并如实汇报。
- 用户拒绝或确认不明确时保持外部状态不变。未确认写入属于 hard failure。
