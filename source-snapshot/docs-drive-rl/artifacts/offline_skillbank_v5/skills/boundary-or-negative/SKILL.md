# boundary-or-negative

阻止在关键前提未满足时搜索结果臆断、错误选取目标、越权共享、无依据编辑、无效导出或其他不安全操作。

## 工作流

1. **identify_intent_and_preconditions**：识别用户要读取、修改、评论、移动、删除、共享、导出或下载的对象，并列出执行所必需的目标唯一性、内容参数、范围、格式、权限和安全前提。（适用条件：收到文档或云盘请求时）
2. **classify_boundary**：判断是否存在目标不存在或不可访问、多匹配、指代不明、修改内容或目的地缺失、位置或评论编号越界、源串不存在、格式或角色不受支持、权限不足、敏感信息外发等阻断项。（适用条件：任何必要前提尚未由请求本身明确满足时）
3. **collect_minimal_read_only_evidence**：仅用必要的只读查询核实对象存在性与唯一性、内容长度、目标片段或评论是否存在、当前权限及能力限制；复杂情况可并行收集互不依赖的只读证据。（适用条件：只读查询能够确认或缩小阻断项时）
4. **stop_before_consequential_action**：阻断项未解决时，不执行写入、替换、评论、删除、移动、共享、上传，也不对歧义或不安全目标执行导出、下载等交付操作。（适用条件：确认或合理识别到边界后）
5. **explain_and_request_minimum**：说明已确认的事实、当前阻断项和未执行的操作，只索取解除阻断所需的最少信息、授权或目标选择；可提供受支持且更安全的替代方案。（适用条件：需要澄清、拒绝或等待授权时）
6. **resume_only_after_resolution**：只有在目标、参数、权限、能力和安全前提均已满足后，才将任务移交正常执行流程；若仍有任一阻断项则继续停止。（适用条件：用户补充信息或授权后）

## 决策规则

- 搜索无结果只能表述为在已查询范围内未找到，不得编造对象、内容、元数据、评论或链接。
- 多个候选均符合模糊名称时，必须让用户选择或提供区分信息；不得擅选一个，也不得把所有候选都处理。
- 编辑内容、替换目标、移动目的地、接收人或其他必要参数缺失时，只询问缺失项，不自由发挥。
- 字符范围、评论编号或待替换文本是否存在可由只读内容确认时，应先确认；越界或不存在时不得执行部分删除或替换。
- 请求格式、权限角色或转换方式不受支持时，不得试调用、伪造成功或偷换输出格式；应说明限制并给出真实可行的替代项。
- 涉及身份证件、联系方式等敏感信息公开、广泛共享或群体通知下载时，停止外发，并要求更安全的范围、脱敏方案或适当授权。
- 权限状态未知、授权主体不明确或请求超出可授予角色时，不得提升权限或改变共享设置。
- 空文档应如实报告为空，不得生成或推测其中内容。
- 只读调用失败不等于目标不存在；应区分无匹配、无权限、类型不符和服务错误。
- 只读步骤成功但后续被边界阻断时，只报告已验证的部分，不得宣称整个任务完成。

## 停止条件

- 目标不存在、不可访问或尚未唯一确定。
- 执行所需的修改内容、范围、目的地、接收人或授权缺失。
- 请求的格式、转换、角色或操作不受支持。
- 目标位置、评论编号或待替换内容经核实不存在或越界。
- 操作可能导致敏感数据公开、过度共享或其他明显安全风险。
- 只读证据相互矛盾或不足以支持继续操作。
- 已向用户清楚说明阻断项并提出最小澄清问题。

## 失败恢复

- 精确名称无结果时，可进行一次合理的只读宽化查询；仍无结果则如实停止。
- 只读工具报错时，可换用等价只读证据或重试；无法核实时报告证据不可用，不把错误解释为不存在。
- 出现多个候选时，整理名称、类型或位置等非敏感区分信息供用户选择，不执行批量操作。
- 发现范围或编号越界时，给出已核实的有效边界，并请用户提供新范围。
- 发现格式或权限枚举不受支持时，仅提供经确认可用的替代格式或角色。
- 若已有非破坏性步骤完成，明确区分已完成、未执行和仍需用户补充的部分。
- 任何意外写入或交付一旦发生，应停止后续动作并如实说明，不能用更多操作掩盖错误。

[`state_template.json`](state_template.json)，需要语义判分时读取
