# multi-source-aggregate

用最少且充分的证据覆盖全部请求来源，产出可追溯的聚合结论，并避免无依据推断、重复调用和未授权写入。

## 工作流

1. **scope_request**：拆分用户请求中的来源范围、筛选条件、所需字段、聚合方式和可选写入动作；为每个明确来源建立待核对项。（适用条件：所有任务）
2. **locate_sources**：按文件名、主题或范围条件定位来源，核对名称、类型等身份信息；明确列出的来源逐一确认，要求“所有”时确认结果范围已完整覆盖。（适用条件：所有任务）
3. **collect_evidence**：仅提取完成请求所需的证据：元数据问题直接读取元数据，内容问题读取对应正文或表格区域；多个独立来源可并行收集，并保留来源到事实的映射。（适用条件：已确定候选来源）
4. **normalize_and_derive**：统一可比较字段的口径，保留证据中的原始单位、时区和精度；再执行分组、排序、公式计算、最值比较或跨文档综合，并复核每项结论。（适用条件：证据已足以支持聚合）
5. **materialize_if_requested**：仅在用户明确要求且目标名称、格式、位置、接收方和权限足够明确时，将已验证的结果写入、导出、上传或分享；不要创建无关中间文件。（适用条件：请求包含创建、导出、上传或分享）
6. **report_result**：按用户要求的结构给出来源事实和聚合结论；写入动作须附成功证据。若部分来源、接收方或权限缺失，明确已完成部分、阻塞项和所需补充信息。（适用条件：所有任务结束前）

## 决策规则

- 用户只询问大小、修改时间、MIME 等元数据时，不读取文件正文。
- 结论依赖正文、表格单元格或金额时，必须取得对应内容证据，不能仅凭文件名推断。
- 明确列出的多个来源必须逐一对应；缺失或歧义来源不得静默替换。
- 要求匹配“所有”文件时，应使用覆盖文件类型的筛选条件，并确认没有未处理的后续结果。
- 数值单位、时间时区和文件名以证据为准；证据未给单位时保留原值并说明单位未知，不擅自换算或补写。
- 增长率按相邻周期计算，并明确基期；分母为零、字段缺失或口径不一致时停止计算并说明。
- 比较最值前确认各来源使用同一字段和口径；并列结果必须如实保留。
- 排序时区分有明确排序键的项目与无日期、日期不完整的项目，后者单独列示，不虚构顺序。
- 创建或分享必须晚于核心证据收集；内容仅使用已验证事实和用户明确要求的结构，不添加无依据的业务判断。
- 接收方身份或权限不明确时，不执行分享；先返回已完成的聚合结果并请求必要信息。
- 已有成功结果不得用完全相同的查询重复获取；格式或工作表不匹配时应检查结构并调整读取方式。
- 动作失败时不得声称完成，也不得用无关文件或额外写入掩盖失败。

## 停止条件

- 全部请求来源均已核对，所需证据充分，聚合结果已复核，且适用的写入动作有成功回执。
- 来源不存在或持续歧义，继续检索无法可靠确定目标；返回缺失项并请求澄清。
- 创建、导出或分享缺少必要的目标、接收方、权限或授权；停止写入并说明阻塞。
- 读取结果缺少核心字段、单位或计算口径，无法可靠比较或计算；停止推导并指出所需信息。
- 工具返回失败或不完整结果，且没有等价证据路径；保留已完成部分并如实报告。

## 失败恢复

- 搜索结果歧义时，使用更精确的名称、类型、目录或内容关键词缩小范围，并重新核对来源身份。
- 文件格式、工作表名称或读取范围不匹配时，先获取文档结构或可用区域，再读取目标内容，避免重复相同失败调用。
- 某一来源读取失败时，尝试适合该格式的等价只读方式；仍失败则标记该来源未完成，不替换为相似文件。
- 单位或时区无法确认时保留工具原值，取消未经证实的标签或换算，并在回复中标明限制。
- 聚合计算复核不一致时，回到原始字段逐项重算，列出公式和输入值。
- 写入或分享失败时停止后续传递，不宣称成功；提供已生成内容、失败环节及可恢复的下一步。
- 接收方缺失时保留已选出的文件或聚合结果，询问明确的账号或群组，不猜测联系人。


## 外部变更授权

- 本节是强制策略，覆盖上方任何将初始请求直接视为执行授权的生成规则。
- 用户最初提出变更只表示意图，不视为确认。
- 未确认时，先完成必要的只读定位与检查，展示具体目标及变更预览，并用一个明确问题请求确认；本轮不得写入。
- 只有在后续用户消息明确确认，或上游提供可信的同消息预授权状态时，才执行变更、验证结果并如实汇报。
- 用户拒绝或确认不明确时保持外部状态不变。未确认写入属于 hard failure。
