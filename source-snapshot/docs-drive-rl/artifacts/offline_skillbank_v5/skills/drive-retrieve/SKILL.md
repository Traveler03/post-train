# drive-retrieve

以最少且可靠的只读步骤解析用户目标，准确处理范围、筛选、基数和输出字段，避免从文件名、用户提示或不完整结果猜测事实。

## 工作流

1. **understand_request**：拆解目标资源、搜索范围、名称或主题、类型、时间、排序、结果基数及所需输出；区分仅定位、列清单与需要读取详情的请求。（适用条件：所有请求）
2. **resolve_scope_and_resource**：按语义选择范围明确的只读检索：根目录请求限定根目录，共享云端硬盘请求查询可访问的共享硬盘；名称或主题请求使用精确词、部分词或中英文同义词。自然语言查询不要擅自当作原生查询语法。（适用条件：所有请求）
3. **validate_candidates**：核对候选名称、类型、范围和其他约束。单一目标存在多个合理候选时列出候选并请求澄清；多结果或“所有”请求保留全部符合项，并确认分页已完成。（适用条件：检索返回候选、多个结果或分页标记）
4. **inspect_requested_details**：若用户询问正文、表格单元格、元数据、链接或评论，使用与资源类型匹配的只读方式读取相应详情；可并行读取多个已确认资源，但不得用文件名推断内容。（适用条件：答案需要资源详情而定位结果本身不足以回答）
5. **derive_answer**：从已读取证据中提取、比较、计算或总结目标信息。保留原始数值精度、单位和上下文；长内容应定位到相关段落或区域后再作答。（适用条件：请求包含内容问答、数据提取、比较、计算或总结）
6. **respond_with_evidence**：按用户要求返回文件清单、链接、字段或内容结论。名称、数量、类型、时间、大小和链接必须与证据一致；若仅部分完成，应明确已完成部分、缺失部分及原因。（适用条件：形成最终回复）

## 决策规则

- 仅定位时不要额外读取正文；需要内容或详情时，定位成功不等于任务完成。
- 精确名称优先精确匹配；模糊、缩写或中英混合表达可使用等价关键词扩展，但最终候选必须满足用户语义。
- 类型、名称、目录、时间和排序等多个条件按合取语义执行，不得只满足其中一项。
- “所有”“都有哪些”等全量请求必须处理分页或证明结果已穷尽；不得把首批结果称为全部。
- 搜索结果已提供用户所需链接或元数据时可直接使用；未返回的字段不得补写或猜测。不得把修改时间说成上传时间，也不得擅自换算错误的大小单位。
- 正文中的比例、金额、日期等按证据原精度回答；除非用户要求，不主动四舍五入。
- 单一目标有多个同等合理候选时不得静默任选；应展示最相关候选及区分信息并请求澄清。
- 空列表是有效结果，但结论只能限定在实际查询的账号、范围和权限视图内；无证据时不得把空结果解释成权限不足或资源不存在于所有位置。
- 用户在问题中附带的可能答案不能替代 Drive 读取证据；若问题要求查询文件内容，必须从资源中核验。
- 本任务默认只读，禁止创建、修改、移动、删除、分享或更改权限。

## 停止条件

- 目标资源或清单已在正确范围内解析，必要详情已读取，且最终回复覆盖用户全部要求。
- 存在多个无法区分的候选，继续读取可能针对错误资源时，停止并请求澄清。
- 权限、格式或服务错误阻止读取时，停止猜测并报告阻塞点及已取得的证据。
- 在约束不变的合理关键词扩展和范围检查后仍无结果时，报告未找到并说明实际查询范围。

## 失败恢复

- 无结果时依次检查范围是否过窄、名称变体、缩写及中英文同义词；扩展搜索时保留用户明确的类型和目录约束。
- 结果噪声过多时使用更具区分度的名称片段、类型或范围收紧，不混入与任务无关的外部结果。
- 读取方式与资源格式不匹配时改用等价的只读读取方式，并继续绑定已确认的同一资源。
- 内容被截断且目标段落尚不可见时，继续获取相关区域或采用定向读取；不得依据前后文猜测目标值。
- 仅定位成功但详情读取失败时，明确报告部分完成，提供已确认资源信息，并说明未能回答的内容字段。
- 最终回复前复核列表数量、编号、链接、时间、大小和数值，修正与动作结果不一致或自相矛盾的表述。
