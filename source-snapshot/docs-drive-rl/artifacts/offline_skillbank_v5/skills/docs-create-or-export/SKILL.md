# docs-create-or-export

以最短可靠路径完成文档产物交付，正确处理源文档定位、复合编辑、格式转换、特殊文件名和目标参数，同时避免修改原件或产生无效文件。

## 工作流

1. **parse_request**：提取操作类型、源文档、目标名称、目标格式、版式、内容修改和交付方式；保留文件名中的空格、符号与大小写，不擅自改写业务值。（适用条件：所有任务）
2. **resolve_existing_source**：需要已有文档时先检索并核对返回对象的完整名称、类型和标识；检索可适度忽略装饰符或空白，但最终选择必须与用户目标唯一对应。（适用条件：复制、编辑、导出或下载已有文档）
3. **materialize_directly**：优先使用能够直接产生所需产物的能力：新建时一次传入明确的名称和版式，复制时保留原件，导出时直接指定目标格式。不要用读取内容或聊天内展示代替文件产物。（适用条件：所有可执行的创建、复制和导出任务）
4. **apply_requested_changes**：复合任务只在目标副本上依次完成全部替换、追加、正文和结构要求；区分正文备注与真正的评论功能。用户已明确章节或字段时直接落实，不因缺少额外业务内容而无故阻塞。（适用条件：产物还包含替换、追加、评论、章节结构或其他编辑要求）
5. **verify_artifact**：核对成功结果中的产物名称、格式或 MIME、访问地址及必要的修改结果；复杂编辑应结合替换计数、写入回执或读取确认检查是否完整。（适用条件：产物生成或修改后）
6. **deliver_result**：简洁说明已完成的操作，给出实际产物名称和可访问链接；仅陈述动作证据支持的格式、版式与修改结果。（适用条件：已取得可交付产物证据）

## 决策规则

- 已有源文档未唯一确定时不得导出、复制或修改；存在多个合理候选时应澄清。
- 优先直接导出或复制，避免先读取、重建再转换造成内容或格式损失。
- 只有直接能力不可用且已取得完整可信的源内容时，才考虑无副作用的等价转换；不得上传占位内容、错误数据或伪造文件。
- 复制后编辑必须作用于新产物，除非用户明确要求修改原文档。
- 用户指定格式时必须生成对应文件产物；在回复中粘贴相似格式文本不等于导出。
- 文件名很长或含特殊字符时，可用宽松检索召回，但必须依据返回的完整元数据确认目标。
- 复合任务以全部明确子要求完成为成功；只创建、只复制或只完成部分替换均属于部分完成。
- 若用户只规定章节结构而未提供正文，可创建包含指定层级和标题的结构化骨架，不应擅自编造业务事实。
- 交付链接、格式、修改计数和版式声明必须来自实际动作结果，不以最终回复或 benchmark PASS 单独证明成功。

## 停止条件

- 已获得正确产物的成功回执，并完成必要校验和交付说明。
- 源文档无法唯一确定，继续操作可能选错对象。
- 权限、资源不存在或转换错误导致无法形成有效产物，且没有经过验证的安全替代路径。
- 继续尝试可能修改原件、创建重复文档、上传损坏文件或产生其他未授权写入。

## 失败恢复

- 检索未命中时，先清理查询中的多余空白或装饰字符并扩大召回，再用完整名称和类型核对；不得猜测资源标识。
- 导出报资源不存在或权限错误时，重新核对选中的资源和授权上下文；不得把错误返回当作成功。
- 直接导出失败时，优先报告真实失败；仅在内容完整、转换可靠且不会新增无关对象时使用等价转换。
- 复合编辑部分失败时，保留已验证的目标对象，补做缺失步骤并重新检查；无法补齐时明确报告未完成项，不宣称整体成功。
- 若误建或误传了临时、重复或损坏产物，应在能力允许时清理；无法清理则明确告知，不得隐藏副作用。
- 同一参数错误连续出现时先检查能力契约或更换安全等价路径，避免重复提交相同失败调用。


## 外部变更授权

- 本节是强制策略，覆盖上方任何将初始请求直接视为执行授权的生成规则。
- 用户最初提出变更只表示意图，不视为确认。
- 未确认时，先完成必要的只读定位与检查，展示具体目标及变更预览，并用一个明确问题请求确认；本轮不得写入。
- 只有在后续用户消息明确确认，或上游提供可信的同消息预授权状态时，才执行变更、验证结果并如实汇报。
- 用户拒绝或确认不明确时保持外部状态不变。未确认写入属于 hard failure。
