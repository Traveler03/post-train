# drive-file-operation

以最少且可靠的步骤完成 Drive 文件操作，确保对象、位置、名称、格式、内容和数量符合用户要求，且不产生未授权写入。

## 工作流

1. **parse_request**：提取操作类型、源对象、目标位置、输出名称、目标格式、数量和内容约束；将复合请求拆成不可遗漏的子结果。（适用条件：所有文件操作请求）
2. **resolve_resources**：对现有源对象和明确目标位置进行解析，结合名称、类型、父目录等元数据排除同名歧义；缺少决定性信息时先澄清。（适用条件：操作依赖现有文件、文件夹或指定目标位置）
3. **select_operation**：根据源类型和用户意图选择直接下载、原生导出、上传、复制、移动、创建或删除；仅在意图明确且源类型兼容时推断输出格式。（适用条件：资源已解析且任务可执行）
4. **execute_and_validate**：执行最小必要操作，并检查返回结果中的成功状态、输出名称、格式、位置、数量和可访问句柄；复合任务逐项核对。（适用条件：所有可执行文件操作）
5. **deliver_result**：仅依据实际结果报告完成项，提供可用文件或访问链接；若部分失败，明确区分已完成、未完成及原因。（适用条件：操作结束或因错误停止）

## 决策规则

- 普通文件要求保留原格式时直接下载；云端原生文档要求其他格式时，按源类型选择兼容的导出能力。
- 用户明确表示要在特定应用中编辑时，可将其视为格式意图，但必须由文件类型和用户措辞共同支持。
- 涉及内容总结、改写或生成文本文件时，先取得源内容；摘要必须由读取到的内容支持，不能仅凭文件名生成。
- 名称、扩展名、目标目录、文件数量和指定内容均属于结果约束，不得擅自更改。
- 复合请求只有在全部必需子操作成功后才能报告整体完成；单个成功不能替代其余步骤。
- 用户已明确发出可执行请求且信息充分时，不以重复确认代替执行；只有存在关键歧义、缺失参数或额外授权要求时才澄清。
- 不得为了绕过导出失败而用不完整内容静默重建源文件，也不得创建用户未要求的中间 Drive 文件。
- 工具层标记成功不等于业务成功；返回错误文本、空结果或缺少输出对象时均应视为未完成。

## 停止条件

- 找不到源对象，或存在多个候选且无法可靠确定目标。
- 输出名称、客户标识、日期规则、目标目录等决定性约束缺失，无法安全推断。
- 目标格式与源类型不兼容，且没有可证明保真的转换方案。
- 操作返回错误、空结果或缺少可验证的输出对象。
- 继续执行会导致未授权的创建、覆盖、移动、删除或额外上传。
- 需要读取内容才能完成摘要或转换，但无法取得源内容。

## 失败恢复

- 源对象未找到时，使用名称变体、扩展名、类型或父目录缩小范围；仍有歧义则向用户列出必要差异并澄清。
- 导出失败时重新核对源的真实类型和目标格式，改用兼容且保真的转换方式；不得用猜测内容重建文件。
- 复合任务部分成功时保留已验证结果，仅重试未完成项，并避免重复创建或上传。
- 写入后结果不明确时，通过输出元数据或目标位置复核；无法复核则报告未确认，而非声称成功。
- 交付链路失败但文件操作已成功时，重新生成可访问交付物；若仍失败，明确说明文件已生成但尚未可下载。


## 外部变更授权

- 本节是强制策略，覆盖上方任何将初始请求直接视为执行授权的生成规则。
- 用户最初提出变更只表示意图，不视为确认。
- 未确认时，先完成必要的只读定位与检查，展示具体目标及变更预览，并用一个明确问题请求确认；本轮不得写入。
- 只有在后续用户消息明确确认，或上游提供可信的同消息预授权状态时，才执行变更、验证结果并如实汇报。
- 用户拒绝或确认不明确时保持外部状态不变。未确认写入属于 hard failure。
